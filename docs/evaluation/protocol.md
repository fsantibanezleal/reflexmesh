# Evaluation protocol and artifact interpretation

Evaluate frozen policies against the same registered candidates, effectors, native broker, controlled fault schedule and independent output predicates. A trained model name is insufficient: the checkpoint, training records, exact configuration and measured export parity must exist. M09-M12 require the configured real planner when their algorithms request one; unavailable providers cannot silently fall back to fabricated decisions.

The core command is `python -m reflexmesh.pipeline evaluate --seeds 10`. The default produces all1200 held-out episodes for each M01-M12. `transfer` runs the separate24-case structural suite. `ablations --seeds 10` runs1200 matched episodes each with M12 memory, effect model, deferral and policy invalidation removed individually. These ablations keep the fitted full-controller gate fixed, so its calibration is not claimed to remain valid after removal of a component. Native permission and resource-version enforcement remain mandatory in every ablation.

`artifacts/evaluation/index.json` provides `schema_version`, generation time, provenance, method/case registries, episode manifest and aggregate results. Every episode manifest entry includes relative path and SHA256. Episode files contain events, decisions, public candidates, raw scores, properly labeled probabilities when available, uncertainty target, predicted and observed effects, residuals, budget, resource revisions, independent metrics and provenance. Real pending planner completions and usage remain in `planner_work` even when they were stale or unused. UI absence of a quantity means not reported, never a fabricated zero.

Controller latency covers the actual policy call, including synchronous planning or bounded cooperative waits. Execution latency covers native admission/effect execution. Wall time includes workspace setup/cleanup and completed background planner work. These quantities must not be interchanged. Provider diagnostics retain prompt/output token counts, provider execution durations and measured request wall time; queue/transport overhead can be analyzed from those values but is not automatically attributed to model computation. This local run is a hardware-specific observation, not a promised latency.

Success comes from independent filesystem, process and HTTP witnesses, not the policy's confidence. A contract violation is reported separately from a failed task and from an unresolved effect. Demonstration-action agreement, its confusion matrix and calibration bins describe the teacher preference target only. M08 and M12 blended scores are utilities; LinUCB scores are optimistic reward estimates; none is silently transformed into a probability.

Malformed policy/provider decisions produce recorded failed cells without admitting an effect. Invalid unused background proposals are reported separately while preserving the task's independently observed success or failure. Provider usage is copied only when actually supplied; unavailable usage remains null. Software transition counts, policy-call counts and cooperative planner hold time are distinct metrics. Environment-seed cluster bootstrap intervals supplement the descriptive Wilson interval; the small, designed cluster population still limits generalization.

Reported Wilson success intervals are explicitly descriptive and rely on independent-episode assumptions that designed families may violate. Family/variant and environment-group comparisons, paired differences and structural-transfer results are needed for stronger claims. One should not infer production failure probabilities from a zero-violation owned-case result. Positive rates near1 on shared templates do not establish open-world competence. Statistical significance alone cannot establish the usefulness of a small absolute gain after planner cost.

The routing target is controlled one-decision incremental utility with shared continuation. Its probability calibrator and threshold selector use separate environment groups. If all paired slow branches are no better than the fast branch, the correct empirical result may be a never-defer gate. M12's separate insufficient-evidence/surprise request remains an explicit design rule and must not be marketed as a learned optimum.

Resumption checks source, native source, checkpoint, specification and dependency lineage before accepting an existing episode. Relevant source or checkpoint changes require a fresh evaluation directory. Infrastructure-error JSONL files preserve failed provider attempts; an incomplete tranche cannot be advertised as the full matrix. The current release report must state which mandatory cells, transfer cases and ablations actually completed, with their artifact hashes, rather than borrowing completion from these protocol documents.

Falsifiable hypotheses are: whether a learned fast scorer improves maintained-rule coverage at comparable constraints; whether recurrence improves history-dependent outcomes; whether effect residuals improve detection/recovery; whether calibrated delegation improves utility after actual model cost; whether affected-resource holds improve accepted useful plans over background-only overlap; and whether the integrated controller transfers better to renamed/composed tools. Null and negative outcomes are first-class findings. The design contains known algorithms and is not evidence of a novel learning theorem, a cognitive equivalence or AGI.
